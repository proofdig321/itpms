## 🚨 CRITICAL ISSUE #1: WBS Owner Assignment

**Problem:** The ownerId field has conflicting requirements - validation expects integers but the database foreign key expects UUIDs.

**What's happening:**
- Your /users endpoint returns UUID strings (e.g., "019efb29-5327-7228-bc6b-06cd9186c5ae")  
- WBS validation rule requires integers: "The owner id field must be an integer"
- But the FK constraint references users.id (UUIDs): `wbs_nodes_ownerid_foreign`
- Result: ALL owner assignments fail regardless of what we send

**Frontend Impact:**
- Responsible Person dropdown is DISABLED with error message
- All WBS nodes created with ownerId: null
- Cannot assign responsibility/ownership

**Quick Fix (Recommended):**
Change your WBS validation rule from integer to UUID:
```php
'ownerId' => 'nullable|uuid|exists:users,id'
```

## ⚠️ ISSUE #2: Sibling Sequence Constraint 

**Problem:** Cannot create child WBS nodes under projects that had previous deletions.

**What's happening:**
- Your unique constraint `uq_wbs_sibling_sequence` includes soft-deleted records
- When we "delete" child nodes, they're soft-deleted but still block new sequence numbers
- Specifically affects ITP-2026-0007 (ICT Service Desk Implementation)

**Error:** "Duplicate entry 'ITP-2026-0007-019f1779-78b9-738a-9745-c11dda215ada-1' for key 'wbs_nodes.uq_wbs_sibling_sequence'"

**Quick Fix Options:**
1. Modify constraint to exclude soft-deleted: `WHERE deleted_at IS NULL`
2. OR hard delete the soft-deleted records for ITP-2026-0007
